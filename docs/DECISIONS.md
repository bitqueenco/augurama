# Decisions · 2026-09-29

**D1 — Independent product, real API.** The earlier concept suggested first-party Dreamina account integration. No such entitlement was established. Ship a BytePlus BYOK adapter and label consumer account/credits/project access unsupported. Revisit only with official supported documentation and authority.

**D2 — Private core / thin hosts.** Protect original recipe/compilation source on the server. Distribute separate host-native metadata and workflow skills. Do not publish the private GitHub repository just to ease installation. Users still see the complete compiled prompt they approve.

**D3 — Human spend gate.** Use a frozen snapshot, expiry, private nonce, transactional job uniqueness and app-only tool metadata. On ambiguous provider outcomes, require reconciliation rather than a repeat charge. No automatic improvement loop, fallback model or bulk spending.

**D4 — Durable single-host service.** SQLite and filesystem media permit a working local/private beta without buying another hosted service. One process and a stopped-service backup lock make its limits explicit. Multi-instance/serverless deployment requires a separately approved durable-store architecture and migration tests.

**D5 — Visible verification boundaries.** Offline Chromium verifies DOM, input and fixture playback because browser network navigation was policy-blocked. Actual TCP tests separately verify service startup/HTTP. Neither is native host, TLS, paid render or semantic-quality evidence.

**D6 — Fail-closed public packaging.** Real origin/source-bound owner evidence is required to mark packages as public submission candidates. The ordinary packages remain local development. This does not replace vendor registration or verify an owner's assertions automatically.
